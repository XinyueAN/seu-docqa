# 现场演示脚本与课程报告建议

## 约 6 分钟演示脚本

### 1. 项目定位与隐私边界（30 秒）

介绍“知序”解决个人文档检索与有据问答问题。指出原始文档、SQLite 索引、聊天会话、图片和评估集存于本机；对话请求会发送当前问题、最近对话上下文和相关检索片段；图片只在用户显式勾选后发给视觉 API。

### 2. 多模态文档入库（1 分钟）

准备课程资料 PDF 和含图表的 PPTX/DOCX。上传时选择分类，展示后台解析进度、文档数量和知识片段数。对需要图像解读的样例显式勾选图片理解，并说明这是可见的云端数据边界。

### 3. 文档解析结果（1 分钟）

点击文档行打开正文预览，展示图片列表、页码和图片说明。解释 PDF 页码较准确，Word 页码按段落位置近似，复杂版式需要核对。

### 4. 会话式问答与追溯（1.5 分钟）

新建会话，提问一个能由导入文档回答的问题；检查中间对话中的 `[S1]` 是否能切换右侧来源证据，并逐项核对文件名、页码、摘录。继续追问一个带指代的问题，再切换到另一会话并切回来，确认历史答案和对应证据可恢复。最后演示一个证据不足问题，观察系统是否表达不确定。

### 5. 混合检索实验室（1 分钟）

用同一关键词/语义问题观察 BM25、TF-IDF、可选 Dense 通道的候选差异和 RRF 排序。若机器已准备 BGE 模型，再启用向量重建索引及 Cross-Encoder，记录启用前后的结果；没有模型缓存时不要把下载过程纳入限时演示。

### 6. 可重复评估和收尾（1 分钟）

使用导入文档的真实名称建立 5–10 条问题/相关文档样例，运行 Recall@K、Hit Rate、MRR。说明这是当前语料和参数下的文档级检索评估；汇报失败样例与边界，并展示 README 的启动步骤。

## 报告建议结构

1. **摘要与问题定义**：个人知识资料的格式分散、检索困难、答案缺乏来源。
2. **需求分析**：功能、数据隐私、可追溯性与本地运行约束；附需求映射清单。
3. **总体设计**：架构图、模块边界、数据流、API Key/图片隐私边界。
4. **关键实现**：doc2md、页面级切片、混合检索、RRF、可选 BGE、AGENTS.md 约束回答和引用渲染。
5. **使用的大语言模型与研发方法**：记录模型标识、日期、提示词约束和模型调用范围。模型结果必须经代码和来源核查；生成式代码应人工审阅。
6. **验证方案**：记录硬件/软件、语料构成、文档数、切片数、问题数、Top-K、配置开关和运行日期。
7. **结果与分析**：填入 Recall@K、Hit Rate、MRR；挑选成功和失败案例，分析解析、召回、重排、生成各阶段原因。
8. **隐私、安全与限制**：本地目录、云端发送条件、密钥不进代码、文件格式和页码近似范围、模型幻觉风险。
9. **总结与后续计划**：可考虑本地 OCR、删除监控文件时同步清理、对话历史/多轮追问、精确 Word 页码、更多文档格式及更系统的离线评测。
10. **附录**：启动方式、配置样例、演示问题、评估集定义、截图及版本信息。
